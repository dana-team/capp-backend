**Purpose:** Describe the architecture, components, flows, and design rationale; detailed API contracts, implementation steps, and per-phase tests are outside this document's scope.

## Summary

For backend maintainers and deployment operators: add opt-in backend authorization for LDAP while production retains existing authentication and authorization. Stage/dev validates the new mode before migration. Scope follows the [plan](../plan.md) and [research](../research.md). The LLD will define schemas, interfaces, and migration procedures.

## Goals / Non-goals

- Preserve platform functionality, editable memberships, and effective access controls through migration; equivalent requests use identical policy semantics across instances, with eventual consistency while policy changes propagate and no fixed propagation deadline.
- In the new mode, users access only capp-backend; backend service identities alone hold Kubernetes credentials and permissions for platform operations. Minimize additional services.
- Exclude authentication redesign, broader OpenShift cleanup, GitOps concurrency, new product capabilities, and disaster recovery.

## Architecture

- **Mode boundary:** legacy behavior remains the default for all existing authentication modes. Enable new authorization only with LDAP; reject incompatible configuration. Supporting it with OpenShift or other identity providers is future work, keeping this implementation small. Passthrough remains legacy-only because it forwards caller Kubernetes credentials.
- **Authorizer:** use embedded [Casbin scoped RBAC](https://casbin.apache.org/docs/rbac-with-domains/) to evaluate identity, action, and target scope. This reuses an authorization library without another service, rather than maintaining a custom evaluator. A small backend integration loads policy, supplies verified LDAP identities, and enforces decisions on every operation, including privileged handlers and cross-cluster actions. Deny unknown operations; never fall back to legacy enforcement.
- **Policy authority and namespace identity:** protected ConfigMaps and Namespace objects on each managed cluster remain authoritative. Each backend replica maintains one shared store per target cluster, with separate policy and namespace generations. Initial loading, watch-triggered refreshes, recovery and local invalidation update both collections; there is no periodic polling or age-based expiry. Compile Casbin only when policy records change. Requests capture the needed generations and keep verified caller identity separate. Every decision checks availability and generation validity before evaluating locally; no per-request policy/namespace authorization reads or decision cache. Namespace discovery reuses cached metadata; resource operations and quota reads still use Kubernetes. Detect concurrent edit conflicts. Preserve the last valid generation during watch/read failures while retrying; fail closed when no valid generation exists or it has been explicitly invalidated.
- **Execution:** in application mode, the cluster manager owns one reusable backend service client per target cluster and replica. Approved requests, discovery, migration and cache refreshes reuse it; no request-specific token or impersonation fields are applied to that shared client/configuration. Legacy caller-scoped clients remain separate. Kubernetes RBAC bounds backend capabilities; application policy bounds caller access. Removing user-binding dependencies makes complete enforcement and caller auditing essential.

## ADR — Watch-driven policy and namespace consistency

- **Status:** accepted on 2026-10-28, superseding the five-second maximum-age decision of 2026-10-26 for both policy and namespace identity. The user accepts eventual consistency with no fixed revocation/recreation-exposure bound, including continued use of last valid policy/namespace data during watch or read failures. The obsolete uncommitted cache implementation was reverted. T06–T11 now deliver reusable clients, evaluators, watch-driven caches and integration as separate reviewable outcomes; implementation and stage validation remain pending.
- **Context:** shared caching removes repeated policy loading, compilation and namespace lookups, but periodic verification still generates traffic when policies rarely change. The user accepts delayed revocation to remove that polling; infrequent updates reduce opportunities for stale authorization, not the impact of a missed removal.
- **Decision:** share validated policy and namespace generations per target/replica, refreshed through initial authoritative LISTs, watch notifications, explicit recovery and local invalidation. Remove periodic verification and maximum-age configuration/enforcement. Retry failed refreshes with capped exponential backoff and jitter until success or shutdown, independently of later events. Make watch/refresh failures observable and keep using the last valid generation during transport/API read failures while retrying. Such failures do not restore an explicitly invalidated generation. Confirmed missing/malformed required policy still invalidates immediately. Recovery explicitly reloads authoritative data even if no object event arrives. Quiet, usable generations do not expire. Keep caller identity request-local and publish complete generations atomically; reject invalidated or superseded captured generations before subsequent decisions.
- **Consequences:** ordinary authorization avoids policy/namespace reads and compilation, and unchanged healthy watches require no periodic verification reads. Replicas may disagree until recovery with no promised deadline. Both silent stalls and detected watch/read failures can retain revoked access; detected failures trigger observable retries while last valid data remains usable. An outage alone does not cause authorization 503 responses when required valid generations exist, although actual resource API operations can still fail. If Alice can read Secrets in `team-a` UID 111 and the name is recreated as UID 222, stale identity and policy can authorize name-addressed access to the replacement until convergence. This exposure has no fixed bound; later convergence cannot undo disclosure or writes. Once UID 222 is selected, UID 111 grants no longer match. Successful membership/namespace writes acknowledge persistence, not all-replica convergence. As optional operator guidance, an urgent revocation can use a manual access outage across all replicas followed by verified reload. This is not a new feature or rollout gate; ordinary revocation relies on eventual convergence.
- **Alternatives:** per-request authoritative reads provide stronger visibility but repeat transfer and namespace lookups. Policy-only caching retains a namespace GET and stronger recreation protection. Periodic verification with a five-second or longer maximum age bounds exposure at the cost of background traffic and expiry during failures; it is superseded, not merely retuned to 30 seconds. Watch-driven updates reduce idle work but cannot promise a deadline, and watch connectivity/bookmarks are not proof of current data. Failing closed on every watch/read error would reduce availability and is not selected; retain fail-closed behavior for absent/invalid policy and explicit invalidation. A separate policy service adds operational dependencies.
- **References:** [requirements](requirements.md#constraints-and-compatibility), [refresh contract](phase-3/lld.md#2-policy-records-and-casbin-integration), [Kubernetes LIST/WATCH](https://kubernetes.io/docs/reference/using-api/api-concepts/#efficient-detection-of-changes), [client-go informer consistency](https://pkg.go.dev/k8s.io/client-go/tools/cache#SharedInformer).

## ADR — Concurrent evaluation of scoped policy

- **Status:** accepted on 2026-10-26; implementation, equivalence tests and stage validation remain pending.
- **Context:** local measurements show exclusive evaluator locking queues callers, while repeated scans of unrelated namespace policy dominate aggregate authorization work even with concurrent readers.
- **Decision:** during policy refresh, validate the entire collection and compile immutable namespace-UID-indexed evaluators containing the namespace's grants and applicable `allNamespaces` grants. Keep cluster-level evaluation separate and provide a shared `allNamespaces` evaluator for explicit all-namespace checks and namespaces without membership records. Use Casbin's synchronized evaluator to allow concurrent readers, with request-local identities and checks of availability and generation validity before returning decisions. Publish all evaluators together as one policy generation; requests never compile policy. Apply the watch-driven consistency contract above and defer decision caching.
- **Consequences:** ordinary checks avoid unrelated namespace rules without weakening permission semantics. More evaluator instances and duplicated all-namespace grants increase generation-build work and memory; compilation affects update convergence and must be measured. Full-collection validation, user/group error propagation, UID isolation and grant equivalence remain mandatory. Namespace metadata refreshes alone do not rebuild evaluators. Lightweight request authorization timing/check counts and separate refresh metrics verify costs; detailed profiling belongs in development/load tests.
- **Alternatives:** an exclusive evaluator lock limits throughput; concurrent readers over the full policy still repeat unrelated scans. Decision caching adds identity-key, eviction and invalidation complexity and is deferred. Short-circuiting subject checks and changing capability responses are not adopted. The separate consistency decision above supersedes the original age limit.
- **References:** [local measurements](phase-3/performance/README.md), [evaluator contract](phase-3/lld.md#2-policy-records-and-casbin-integration).

## Data model

- Bind canonical users/groups to actions within cluster/namespace scope; preserve distinctions between resource access, namespace administration, and membership delegation.
- Combine matching user/group allow grants within their explicit scopes; deny without a matching grant. Cluster grants cover namespaces only when explicitly scoped to do so. Delegation grants specify which permissions the caller may assign; resource access alone grants no implicit delegation.
- Membership operations use application policy in the new mode and RoleBindings in legacy mode. General resource endpoints cannot expose or modify protected policy.
- Namespace memberships remain bound to an instance UID. Deletion/recreation stops matching old grants once reflected in the namespace cache; use of the old identity is accepted until convergence, without a fixed maximum delay. Preserve UID preconditions on namespace deletion. The LLD defines identity caching, binding and cleanup.
- The fixed Casbin model ships embedded in the backend binary and changes with a rebuild; roles and bindings remain runtime policy in ConfigMaps. The LLD specifies the model and ConfigMap mapping, including delegation limits and namespace identity; the backend retains ownership of policy validation, persistence, and enforcement.

## Workflow / Sequence

- **Resource access:** verify identity → resolve target and configured namespace restrictions → evaluate policy → execute with backend credentials. Restrictions remain an additional boundary.
- **Discovery:** apply action/scope checks to namespace and aggregate resource lists, including Capps, ConfigMaps, and Secrets; return only authorized items, totals, and capabilities. Projects/SSAR filtering remains in legacy mode.
- **Membership changes:** authorize the caller's delegation rights, then persist the scoped policy change. Publish grants only after required namespace/quota setup succeeds.
- **Cross-cluster operations:** authorize source and destination actions before side effects; deny if either check fails. Writes remain non-transactional across clusters.

## Rollout stages

1. **Coexisting authorization modes** — ship legacy behavior by default; explicitly enable the new mode in stage/dev with protected policy storage and backend credentials. Keep replicas behind each endpoint on consistent mode/configuration.
2. **Controlled migration** — map effective permissions, including existing membership-delegation rights and custom grants. Briefly freeze membership changes for final reconciliation before switching traffic; no automatic dual-write synchronization is assumed. Require acceptable listing latency and policy-read volume, with budgets defined in the LLD. Retire user Kubernetes grants to complete the backend-only boundary. Rollback must reconcile policy changes and may require restoring reviewed legacy grants, temporarily restoring legacy access.

## Security / Failure modes

- Fail closed before a required collection is loaded, on confirmed missing/malformed required policy, or after explicit local invalidation/shutdown. Transport/API read failures preserve an otherwise valid generation while recovery retries; a failed read is not proof that policy is missing. Recover through authoritative reload and resumed observation; distinguish dependency failures from denials. A usable complete namespace collection lacking a name produces the existing namespace-not-found response, not a fallback GET. Quiet caches do not expire solely with elapsed time. Failed policy writes report failure.
- Protect credentials and policy from resource endpoints and user-controlled workloads; only authorized membership flows may alter policy.
- Changes affect new authorization decisions as replicas converge, without a fixed maximum delay. A silent stall or detected watch/read failure can preserve old grants, old namespace identity, or false denials until recovery. Already-authorized operations may finish. Token-carried groups retain existing authentication freshness limits; token expiry does not bound stale policy because an otherwise valid user can log in again.

## Observability

- Audit caller, action, target, evaluated namespace UID, policy/namespace collection versions, mode and outcome; correlate service-identity operations without credentials. Measure request authorization duration/check counts separately from Kubernetes operations and end-to-end latency. Monitor collection availability, watch errors/reconnects, retry state, time since last successful authoritative load, refresh failures/duration/bytes, compilation, denials and configuration drift. Age and event silence are diagnostics, not expiry rules or proof of a stuck watch. Use bounded metric labels and request-level aggregates without identity/namespace/version labels; detailed profiling belongs in development/load tests.

## Assumptions

- Stage/dev and production use separate deployments; instances share canonical identity mapping, cluster identifiers, and compatible configuration.
- Operators provision protected policy storage and initial administrative grants. Existing custom permissions require inventory and explicit mapping; they are not assumed equivalent to default CAPP membership.
